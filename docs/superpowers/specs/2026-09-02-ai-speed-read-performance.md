# AI 速读性能优化设计

## 目标

解决手机运行 AI 速读时的异常发热风险，降低流式生成期间的 CPU、布局测量和内存压力，同时保持生成内容、流式展示、停止、缓存、导出与分享行为不变。

## 硬约束

- 关闭 AI 速读面板不得终止生成；重新打开后立即恢复到最新进度。
- 不改变提示词、模型请求、分段策略、输出内容、缓存键或分享效果。
- 不引入生产依赖。
- 离开当前文章或显式点击“停止”时仍按现有行为取消当前任务。

## 根因与证据

1. `ReaderScreen` 直接持有 `thinking`、`markdown`、`status` 三份流式状态。约每 80ms 的 partial 会触发整个阅读器组件树重渲染，而真正需要刷新的只有 AI 速读面板。
2. 墨水屏分页的 `measureKey` 包含速读文本长度，但速读面板通过 portal 挂到 `document.body`，不属于被测量的正文 DOM。生成过程中因此反复测量整篇正文，属于无效布局工作。
3. 流读取器没有显式释放 reader lock。正常结束通常会由 GC 回收，但取消和异常路径缺少确定性资源清理。
4. 关闭面板后虽然已停止 React state 更新，流式结果仍保存在 ref 中。把它迁移为可订阅快照可以隔离整页重渲染，同时原样保留后台生成与恢复能力。

## 方案

- 新增轻量 `SpeedReadPartialStore`：任务始终写入最新快照；面板打开时订阅，关闭时取消订阅。
- `ReaderScreen` 只保留低频的任务状态和最终 Markdown；流式 partial 不再触发整页 state 更新。
- `AiSpeedReadPanel` 用 `useSyncExternalStore` 读取快照，关闭时使用空订阅，重开时同步取得最新快照。
- 墨水屏分页键只反映正文、翻译和加载状态。
- 流读取循环用 `try/finally` 确保 reader lock 在成功、失败、取消路径都释放。

## 完成标准

- 快照存储在无订阅者时仍保留最新 partial；重新订阅可立即读取。
- 相同快照不触发重复通知，取消订阅后不再通知。
- AI 速读原有序列化、调度、取消测试全部通过。
- lint、TypeScript/Vite build 通过。
