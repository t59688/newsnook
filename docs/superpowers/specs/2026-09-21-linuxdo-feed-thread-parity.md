# Linux.do 信息流与主题详情对齐规格

## 背景

NewsNook 已能读取 Linux.do 的 Discourse JSON API，但信息流加载反馈、安全验证回流、筛选导航和回复关系展示仍与 Linux.do PWA、FluxDO 存在明显差距。

## 目标

- 信息流和主题详情使用可辨识的加载骨架；加载更多使用持续可见的进度反馈。
- 从安全验证页点击“完成”后立即重试原请求，不保留旧的验证错误界面。
- 信息流中的分类和标签可点击，并在站内打开对应主题列表。
- 主题详情显示每条回复的目标用户；点击回复目标可定位到被回复楼层，并保留返回原楼层能力。
- 常见 Discourse 正文元素在清洗后保持语义和可读布局，不执行不受信任脚本。

## 范围

本轮只覆盖匿名可读链路和现有主题详情组件，不新增生产依赖，不改变 Linux.do API，不实现完整 Discourse 客户端，也不复制 FluxDO 的 Flutter 架构。

## 验收标准

1. 安全验证函数成功返回后，信息流执行一次新的第一页请求；失败时仍展示可重试错误。
2. 分类/标签点击不会同时打开主题，且可加载对应分类/标签主题。
3. `reply_to_user` 被解码为类型安全字段；回复指示器显示头像/用户名并可跳楼。
4. 骨架 shimmer 在普通动效设置下持续运行；`prefers-reduced-motion` 和墨水屏下关闭。
5. Linux.do 单测、lint、build 通过；Android APK 可覆盖安装到 `emulator-5554` 并保留数据。
