# InkPlayer 应用内悬浮播放设计

日期：2026-10-10  
状态：用户已批准，已实施；验证记录见实施计划。

## 1. 目标与范围

用户希望一边播放视频，一边浏览应用内其他页面。播放器应能脱离母页，在应用顶层拖动、调整窗口尺寸，切换全屏、恢复播放页和关闭，并完整管理生命周期。

覆盖所有已经交给 `InkVideoPlayer` 的可播放资源，包括阅读器视频、正文内嵌视频、YouTube 发现后的资源、视频页和原站嗅探后的自定义播放器。原站 iframe / 原生 WebView 尚未发现可交接资源时，不显示悬浮按钮。

沿用本地优先、直连上游、现有网络与鉴权边界；不新增生产依赖、状态库、路由库、云接口、持久化格式或 Android 系统悬浮权限。此功能为应用内悬浮，不扩展系统 PiP 或后台音视频服务。

完成标准：母页卸载后仍能在其他页面播放；展示模式切换不重建同一媒体的 video / HLS / DASH 引擎；操作不会留下声音、原生方向锁、亮度覆盖、滚动锁、监听器或异步更新泄漏。

## 2. 现有实现与方案选择

已检查的入口：

- `src/components/InkVideoPlayer.tsx`：外层处理延迟加载、资源选择与媒体页；内部 Ready 组件拥有播放引擎、手势、全屏、原生方向和清理。
- `src/components/inkVideoPlayer/lifecycle.ts`：按 URL 与格式区分播放身份，鉴权变化可按检查点恢复；发现元数据变化不能重启播放。
- `src/components/InlineArticleVideos.tsx` 与 `src/lib/inlineVideoFullscreenHost.ts`：稳定 portal 容器及全屏时移动宿主已存在，但 React 子树仍归母页所有。
- `src/lib/hardwareBackStack.ts`：现有 LIFO 返回键浮层栈，可继续复用。
- `src/components/OriginPlayerSurface.tsx` 与 Android `MediaSnifferPlugin.java`：原站实时嗅探 WebView 是 Activity 中单独添加的原生视图，不能由 DOM z-index 覆盖。
- `scripts/ink-video-lifecycle.test.tsx`、`scripts/ink-video-live-updates.test.tsx`：已有真实 React 组件与模拟媒体解码器的生命周期回归测试。

| 方案 | 优点 | 代价与判断 |
|---|---|---|
| 应用级会话拥有播放器；稳定 portal 容器在各展示位之间移动 | video 与引擎实例连续，母页卸载后仍可存活；复用现有播放能力 | 需要明确页面与会话的所有权，推荐 |
| 悬浮时创建第二个播放器，再转移进度 | 初期改动较少 | 重建缓冲与鉴权、直播难恢复、双声音与异步竞态风险；不采用 |
| 持续挂载隐藏母页 | 可以暂时保留播放 | 隐藏阅读器继续运行嗅探、正文效果和订阅，不具备独立生命周期；不采用 |

## 3. 使用体验

### 3.1 入口与模式

内嵌与全屏控件增加“悬浮播放”按钮，使用现有 lucide 图标。播放器已解锁且资源可播放后可用；正在加载仍可悬浮，未解锁的媒体占位不提前联网。

悬浮默认出现在右下角，位于底部导航和安全区上方。母页留下原尺寸占位，展示封面及“正在悬浮播放 / 恢复到此处”入口，避免正文跳动。占位不会创建第二个播放引擎。

| 模式 | 展示 | 离开母页后的行为 |
|---|---|---|
| 内嵌 | 原页面的视频位置 | 保持原有卸载即停止的语义；只有用户明确悬浮才跨页面存活 |
| 悬浮 | 全局小窗，无页面遮罩 | 母页可以正常卸载，会话独立存活 |
| 独立播放页 | 应用内播放页，提供标题、资源与完整控制 | 不要求重建母页；返回后缩为悬浮 |
| 全屏 | 沿用系统方向切换和浏览器 / Android 兜底 | 退出回到进入前模式；母页已失效时回到悬浮 |
| 关闭 | 窗口移除，媒体停止 | 同步撤销会话操作权限，异步完成资源清理 |

“恢复播放页”：母页对应的视频位仍挂载时归位；否则打开独立播放页，不为了恢复视频重建文章或工作区。独立播放页沿用现有媒体资源页面的布局。

### 3.2 小窗布局与视觉

小窗使用现有播放器深色画面与纸白控件，圆角 12px、细边框、克制的阴影。墨水屏遵循现有模式，减少阴影和过渡。播放画面保持原比例并用 contain 显示。

- 顶部为 44px 操作栏：截断标题作为拖动区域，恢复播放页与关闭按钮始终可见。
- 画面中心为播放 / 暂停，加载时显示缓冲状态；播放中约 2.5 秒隐藏画面控件，点击画面唤出。
- 底部显示紧凑进度与全屏入口；窗口太小时隐藏时间数字，保留操作按钮。
- 右下角提供可见的缩放把手，触控区域至少 44×44px。
- 倍速、投屏、资源选择等完整能力在恢复播放页 / 全屏后使用，避免小窗控件堆叠。悬浮时隐藏原有全局嗅探 FAB，避免窗口与 FAB 重叠。

悬浮层无整屏遮罩，外围容器 `pointer-events: none`，窗口本身接收输入。应用页面、设置和工作区可以正常操作。窗口位于应用页面和普通弹层之上；播放器自己的资源选择 / 投屏弹层在窗口之上。涉及浏览器 top-layer 的全屏与原生 WebView 单独处理，不能以增加 z-index 代替。

### 3.3 拖动与缩放

- 使用 Pointer Events 与 pointer capture；顶部标题区拖窗，右下把手缩窗。画面区域保留播放点击，悬浮模式禁用原有视频画面捏合、平移、亮度和音量手势，避免争夺输入。
- 双指捏合小窗调整窗口尺寸，以两指中心为基点，按当前窗口比例缩放；不改变视频画面的内部 scale。
- 保持画面比例，顶部栏高度单独计入。默认画面宽度为 `clamp(220px, 可用宽度 × 0.60, 360px)`，最小画面宽度 200px，最大画面宽度为 `min(640px, 可用宽度)`；所有尺寸再受可用高度限制。小于最低空间时优先保证窗口及关闭按钮完整可见。
- 拖动自由定位，不强制贴边；抬手时仅将超出部分限制回可见范围。定位范围扣除四向安全区并留 8px 边距。
- 默认避让底部导航；拖动时允许用户放到其他安全区内的位置。
- 横竖屏、视口、软键盘和安全区变化时重新限制尺寸与坐标；全屏往返恢复最近的小窗位置与大小，不回到默认值。
- `pointercancel`、捕获丢失、窗口失焦、模式切换和关闭都结束交互，清理指针与临时倍速，不出现持续拖动。
- 拖动更新使用 requestAnimationFrame，不在每次移动时更新整个应用或写持久化存储；不依赖较新 WebView 才支持的 CSS 独立 translate / scale 属性。

首次进入小窗显示一次可消失提示：“拖动标题移动，拖动右下角调整大小”。触控、鼠标都可用；标题拖动柄支持键盘方向键移动，缩放柄支持方向键调整尺寸，Shift 提供较大步长。图标按钮有中文 aria-label 与可见焦点。

## 4. 会话架构与所有权

新增 `src/features/floatingVideo/`，只负责播放器会话、展示模式与窗口交互，播放引擎继续复用现有模块：

| 单元 | 职责与边界 |
|---|---|
| `types.ts` | 会话 ID、播放输入、宿主注册、展示模式和运行时操作句柄的类型契约 |
| `session.ts` | 应用范围会话管理；register / update / detach / float / restore / close；订阅快照与会话代次 |
| `FloatingVideoProvider.tsx` | 在 App 页面分支之外创建并销毁管理器，提供 Context；用现有 React 能力，无模块级可变单例 |
| `VideoSessionHost.tsx` | 持有播放器 React 子树与稳定 DOM portal 容器；按模式移动宿主，独立于页面挂载 |
| `FloatingVideoWindow.tsx` | 小窗外壳、可达性、拖动与缩放输入；不拼媒体 URL、不管理鉴权 |
| `geometry.ts` | 安全区、窗口比例、坐标限制与缩放纯函数 |

`InkVideoPlayer` 公共入口成为兼容的宿主适配器：保留现有 props、延迟加载与句柄语义，向应用会话注册播放输入和挂载位置；内部运行时迁移为可由 Host 渲染的单一组件，不复制现有 HLS / DASH 与手势实现。没有 Provider 的独立测试 / 独立嵌入保留原有内嵌能力，不显示不可用的悬浮入口。

应用 Host 是已加载播放器的 React owner，页面只拥有 slot 和附件。切换展示位置时稳定的 portal container 不变，只改变 DOM 挂载点；不能通过切换 createPortal 的目标节点重挂播放器。现有正文 fullscreen host watcher 必须与会话 Host 分工，只有一个模块拥有宿主迁移权，避免双方来回移动 DOM。

会话按 slot 身份区分，不能只用 URL：同一地址可能出现在不同文章并使用不同鉴权上下文。媒体引擎身份继续复用 `playbackIdentity`，资源元数据更新、拖动、主题和母页标题变化都不构成重建条件。

页面卸载时 detach：内嵌会话销毁；已经明确悬浮的会话保留播放输入快照并解除页面回调引用。与卸载页面绑定的刷新 / 错误回调不再调用；悬浮会话显示自己的错误和重试，签名地址过期时提示“返回来源页重新探测”，不假装能在缺少源会话时重新生成地址。

同一来源页面重新出现时，只有明确匹配的 slot 契约才能接回已有会话；不依赖数组序号或裸 URL 自动抢占。无法匹配仍保留悬浮，用户可在独立播放页操作。

## 5. 生命周期与并发规则

展示状态与媒体状态分离，媒体状态包含未加载、加载中、播放、暂停、缓冲、结束、错误和关闭。展示模式变化只修改布局，不改变播放意图。

| 事件 | 结果 |
|---|---|
| 内嵌 → 悬浮 | 先退出全屏 / 临时手势状态，保留 video、引擎、缓冲、倍速和暂停意图，再迁移展示 |
| 悬浮 → 全屏 → 返回 | 系统栏、方向、亮度沿用现有控制，按序还原后回小窗；不移除会话 |
| 母页关闭 / 切工作区 | 只撤销母页附件；悬浮继续，未悬浮则按原语义停止 |
| 第二个视频请求悬浮 | 最多一个悬浮会话；先暂停并关闭旧悬浮会话，再把新会话悬浮，旧窗口不叠加 |
| 用户主动播放其他 InkPlayer | 暂停当前悬浮视频并保留窗口，不自动恢复；避免两个 InkPlayer 同时发声 |
| 新页面仅加载另一视频 | 不抢播放焦点、不更改悬浮会话的鉴权上下文；原生媒体准备必须保证会话隔离 |
| 应用 / Web 页面后台或锁屏 | 暂停本地 video，解除临时手势、方向与亮度覆盖；回前台保留窗口与进度，由用户点击续播 |
| 播放结束 | 保留窗口并显示重播入口，不突然消失 |
| 网络 / 解码失败 | 保留窗口、关闭和恢复按钮，展示可读错误；按现有协议重试，不循环自动嗅探 |
| 用户关闭 | 立即禁止新操作并撤销异步回写权限，暂停，清理引擎与 DOM，最终移除会话 |
| Provider 卸载 / StrictMode 清理 | 清理所有 owned 会话与全局订阅，重复清理幂等，不影响后来创建的会话 |

全屏进入 / 退出串行化；关闭优先于未完成的转换。媒体准备、动态 import、方向切换、play Promise 与资源刷新都检查会话 ID 和代次，旧会话晚到的响应不能修改新窗口、恢复播放或解锁新会话持有的原生状态。

销毁覆盖：video pause / 移除 src / load，HLS destroy、DASH reset、媒体事件、计时器、rAF、ResizeObserver、MutationObserver、指针捕获、视口 / 可见性监听、返回键注册、滚动锁、portal host，以及播放器持有的全屏、方向与亮度状态。

DLNA 电视播放继续遵循现有测试契约：关闭本地播放器不隐式停止电视播放；不为悬浮改动远端投屏生命周期。

## 6. 返回键、全屏和原生视图

Android 返回键与 Web Escape 按当前展示上下文处理：先关闭播放器内部菜单，再退出全屏；独立播放页返回缩成小窗。普通小窗不注册消费页面返回键的处理器，用户可以正常离开当前文章、设置与工作区；关闭由明确的关闭按钮触发。

复用现有 hardware back 栈；悬浮全屏的处理由应用 Host 注册，不依赖 ReaderScreen 仍挂载。兼容旧 fullscreenHandleRef，避免页面返回与全局返回重复消费。

原站实时 WebView 位于主 WebView 之外。初版使用明确的原生可见性协调：全局悬浮 / 独立播放页 / 视频全屏存在时，暂停并隐藏原站 native live surface，页面保留“关闭悬浮后可使用原站播放器”的提示；窗口关闭后只恢复仍有效页面的 live session。嗅探候选仍可按现有能力更新。恢复不得针对过期 sessionId，也不得在已卸载页面重启嗅探。

这意味着用户仍可浏览所有应用页面，但悬浮期间不能同时操作另一个原生原站播放器。该边界必须在 UI 和真机验收中体现；不把原生图层问题掩盖成已支持。如果未来要求两种原生 / DOM 画面同时显示，则另立原生合成方案，不在本次引入第二个 WebView 播放壳。

原生鉴权准备与串流代理也要验证隔离：另一 slot 初始化不能覆盖当前会话依赖的 Referer、Cookie、headers 或 stream proxy context。若现有桥接上下文共享，应在已有 native 播放契约内做会话隔离，生命周期负责释放对应会话，不能清空其他存活会话或日志输出凭证。

## 7. 验证与交付

新增行为测试，沿用 scripts + tsx / linkedom 的现有习惯：

1. 用同一真实 React video 节点验证内嵌 → 悬浮 → 全屏 → 恢复过程中元素身份、currentTime、paused、倍速与 load 次数不变。
2. 悬浮后卸载母页、切换页面、更新资源元数据；视频继续，旧页面回调已撤销；关闭后没有残留 video、监听和返回键注册。
3. 母页不存在时恢复到独立播放页，关闭播放页回悬浮；源更换、鉴权变化按已有身份规则处理。
4. 快速悬浮 / 全屏 / 关闭、方向异步响应晚到、播放 Promise 晚到、StrictMode 重挂；关闭会话不能复活。
5. 拖动、角落缩放、双指缩放、取消、键盘输入、极小视口、软键盘与四向安全区，窗口和关闭按钮保持可达。
6. 单悬浮替换、主动播放其他视频、原生准备隔离、应用后台暂停、不自动续播。
7. 返回键可以退出悬浮全屏而不关闭页面，普通小窗不吞页面返回；投屏不被本地关闭误停。
8. 原站 WebView 可见性协调与 sessionId 失效场景，不出现原生视图遮住小窗或重复声音。
