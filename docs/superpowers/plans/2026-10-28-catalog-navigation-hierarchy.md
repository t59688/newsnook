# CMS 导航层级与列表语义修复

**目标**：CMS 浏览保留“全站导航 → 当前栏目子导航 → 内容”的关系。榜单和专题入口可打开；文字排行、海报列表和无内容的导航入口分别处理，不影响普通浏览器及新闻/RSS。

**证据**：实际 Android OkHttp 请求取得 qiyunzl 首页、榜单首页、电影/电视剧榜单，均为 200。旧解析器对后三页返回 unsupported、0 条；榜单总页含 4 组各 10 条文字链接，分榜单各含 60 个海报/标题配对容器。次级导航在独立 box-title-nav 中；全站栏存在榜单 active 状态。页面加载 /zanpian/ 模板资源及 Bootstrap/jQuery，没有可证实后端语言或版本的标记。

## 不变量与取舍

- 不根据域名、固定频道名或猜测 API 适配；只读取响应中真实链接与 DOM 关系。
- CMS 身份与可用能力分离。模板资源不是后端指纹，不据此把普通图文内容强制变为视频。
- 不新建站点爬虫或持久化导航树；导航上下文跟随 CatalogPage，现有 CatalogProfile.categories 仅承载向后兼容的一级入口。
- 二级入口、筛选、分页、播放控件不得污染一级入口。切页/切站时页面上下文更新，不能累积旧子菜单。
- 请求失败保留最后成功页面；取消/过期响应不得替换当前页面。
- 无结果、只有导航、访问受限、动态空壳、详情页必须区分。
- 用既有主题与横向导航栏表达两级关系，不重做播放器或浏览器。

## 实现步骤与验证

1. `scripts/catalog-navigation.test.ts`：先证伪一级/二级分离、当前选中项保留、导航页非错误、文字排行、非标准海报容器、侧栏排除、失败/竞态、切栏目不泄漏子导航。
2. `features/siteCatalog/navigation.ts`：依据 DOM 导航容器、嵌套关系、当前链接/active、同站 URL 发现页面级 groups 和 activePrimaryUrl；规范化仍走已有 context/navigationRoles。
3. `types.ts` / `capabilities.ts` / `service.ts` / `session.ts`：加入可选页面导航和 navigation 页面类型，保留旧 profile 契约，删除无边界 categories 累积合并。根级菜单与响应级菜单职责分离。
4. `catalogEngine/extractors/domCards.ts`：用匹配的海报与标题链接推断最小卡片；用重复编号列表识别文字排行；侧栏、导航、作者及推荐区域继续排除；保持来源顺序及内容 URL。
5. `SiteScreen.tsx`：一级行标为全站导航，当前页面子栏目独立第二行，父子分别选中；导航入口页提示选择子栏目而非访问异常。沿用颜色/字号/按压反馈；不加装饰性动效。
6. `scripts/site-navigation-ui.test.tsx`：从一级点击榜单，再点击电影/电视剧榜单；验证选中项、文章打开与 sourceId、刷新/失败、切回普通分类。
7. 核查 parseCatalogPage 实站样本；运行 site-catalog/catalog-engine/framework-detect/相关正文与播放器/浏览器测试、lint、生产构建。备份模拟器私有数据和 APK 后覆盖安装，验证真实点击全链路与两级界面；推送同分支。

## 评审重点

- 站点未给 nav 标签，仅模板样式类；嵌套菜单与平铺局部菜单都保留层级。
- 榜单列表没有图片，不得因低卡片分数丢失。
- 海报中带 1080P 徽章而标题在相邻节点，不把徽章误判为唯一标题或播放控件。
- 子栏目使用相同 URL 搭配 query，必须保留业务参数；分页不能冒充子栏目。
- 空首页有主导航不能随便判成有效内容；只有受证实的上下文子导航可判 navigation。

## 导航层级与榜单列表（2026-10-28）

`CatalogProfile.categories` 保留向后兼容，只表示一级站点入口，不再把每页出现的子菜单累积为全站分类。响应级 `CatalogPage.navigation` 包含 `activePrimaryUrl` 与当前页面的子导航 groups；不持久化 HTML、DOM 或整站导航树，不改变备份/同步协议。界面以一级导航与独立子栏目行表达，父子选中状态分别来自最后成功响应，失败请求不会给旧列表贴上新栏目的选中标记。

`navigation.ts` 识别语义导航、模板局部导航容器、嵌套列表归属、当前 URL 和 active/aria-current。实际查询参数完整保留；在查询型子栏目仅标记子项时沿 DOM 祖先追溯父栏目；三级菜单按最近列表分别归属，不覆盖二级父节点。分页、排序、筛选、播放控件及侧栏不进入一级菜单。当前页链接不因 URL 与页面相同而被删除。

页面类型新增 `navigation`：有实际上下文子栏目但无内容条目的页面可以继续浏览，不抛“此页面不是目录”。仅有全站页头、验证码、未知动态空壳或详情页仍使用各自状态。没有猜测接口、自动爬遍子页或新增网络服务。

`collectionStructure.ts` 用相同 URL 的标题与海报寻找最小卡片容器，避免固定某个 CMS 类名；重复编号的纯文本列表同样可构成目录，保持上游顺序。DOM 主抽取与启发式回退共享非内容区域边界，防止侧栏/导航在回退路径重新混入；作者头像/署名等元信息不因图文配对被提升为正文。单条合法海报仍保留。

### 实站与回归证据

Android OkHttp 返回的 qiyunzl 页面：主页 38 条；榜单总页 40 条文字条目；电影、电视剧、动漫、综艺榜单分别 60 条；人气明星页本次响应没有内容条目，保留其真实子导航供继续浏览。旧解析器对总榜、电影榜和电视剧榜均返回 0 条 unsupported。

实际页面资源有 `/zanpian/` 模板、Bootstrap 与 jQuery 特征，可确认赞片系前端模板线索；没有足够证据确定后端语言、产品分支或版本。因此继续使用通用身份与真实页面能力，禁止仅因模板名套用猜测的 CMS API 或将混合内容全部强制标为视频。

新增 13 项结构/会话回归及真实 React UI 流程测试，均经历先失败再通过。独立只读审查发现的查询子菜单、三级归属与作者头像误判已补回归修正。相关 CMS、目录引擎、框架识别、正文、RSS 视频、浏览器、播放器套件及 lint/生产构建通过。模拟器实测主导航 → 榜单 → 电影/电视剧子榜单 → 普通电影栏目 → 重入榜单，数量、两级选中与上下文清理均有响应证据；页面数量以当次上游内容为准，不能等同于所有 CMS/主题实站覆盖。
