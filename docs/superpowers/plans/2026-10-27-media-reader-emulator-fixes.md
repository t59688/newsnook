# 视频识别与 CMS 目录：模拟器回归修复

基线：`893228c0f470b8843006d9fccfa1bb76c966492b`，分支 `feature/media-sniffer-production-v2`。

## 实际复现与根因

1. Chromium 对空 `video[src]` 的 `src` 属性返回当前文档 URL。原探针采用该属性兜底，分类器又把 `mediaKind: video` 当作充分证据，将 HTML 详情页变成 progressive 资源。模拟器实际请求了详情页对应的本地流代理，解码错误码为 4。
2. 原站隐藏后的文档恢复会产生新的文档 epoch。旧实现因此重新允许自动切换；返回原站、人工辅助期间尚未完成的异步准备也会重新覆盖用户选择。
3. 阅读器的独立详情请求没有沿用目录抓取的 HTTP 客户端、UA 与 WebView Cookie。相同详情页在模拟器中出现默认请求 404、目录 OkHttp 请求 200 的差异，自动探测无法继续发现播放线路。
4. 播放地址 Tab 的 `#fragment` 和推荐海报上的清晰度徽章混入有限探测队列，实际 HD、720P 线路得不到完整探测机会。
5. Bootstrap 栅格把每个条目套在独立列节点中；按卡片直接父元素分组造成多个单条列表。实际页面有 48 个条目，旧 DOM 提取只留下 1 条。
6. `pagination1`、三角形下一页按钮、带省略号的末页计数没有被识别为分页角色，进入顶部栏目并污染保存的能力信息。

## 修改边界

- 探针只读取明确、非空的媒体属性；分类器拒绝 HTML 响应、无媒体 MIME 证据的文档路径和当前文档回指，仍允许真实媒体 MIME 的无扩展名端点。
- 人工选择原站后取消待完成切换，并在文档 epoch 变化时保留选择。每个原生异步操作结束都核对代次；人工切换发生在隐藏操作执行期间时，恢复原站的可见性与交互，避免空白。主动重新识别或打开新条目才开始新一轮自动流程。
- 阅读器使用已有 `catalogRequestOptions`，沿用配置 UA、OkHttp、WebView Cookie 和已有代理策略，不增加另一套网络实现。
- 页内标签、当前文档、推荐海报不作为次级播放器页面；实际线路继续参与探测。
- 结构化识别栅格包装层及同层重复列表，保留语义区域边界和单条列表。
- 分页角色共用于栏目筛选、下一页发现和保存配置的清理；保留合法栏目、数字栏目与年份筛选，不清空用户配置。
- 不修改普通浏览器的主动行为，不增加域名特例、依赖或存储格式变更。

## 模拟器实测

设备：Android 12 x86_64 模拟器。仅使用 `adb install -r` 更新调试包，更新前备份私有数据和原安装 APK。首次安装时间未改变，原预设仍在。

- 实际影视详情自动发现 HLS，无需点击原站控件。内置播放器达到 `readyState = 4`，实测视频为 1920×800、时长约 5296.92 秒，播放时间持续推进至 25 秒以上，无媒体错误。
- 截图中的“血话童真”也完成同样验证：自动发现 2 个资源，实际解码 1920×1080，时长约 7580.92 秒，播放时间持续推进；最终安装包复测通过。
- 点击“返回原站播放器”后连续 12 次采样（间隔 600ms），保持原站辅助模式，没有重新出现内部播放器或播放失败页。
- 实际 CMS 首页显示 48 条；“最新”第一页、第二页各 24 条；返回上一页后恢复 24 条。顶部栏目没有省略号页码和三角分页按钮。

## 回归入口

- `test:media-sniffer`：原有套件及新增空 src、HTML 候选、真实 MIME、线路目标测试。
- `test:ink-video-live-updates`：人工模式保持、迟到准备回调、目录 HTTP 身份一致性。
- `test:site-catalog`：栅格多行、多区域、单条列表、语义分页、保存信息修复及数字筛选保留。
- 实际注入脚本测试直接读取 Java text block，模拟 Chromium 的空 src 属性解析行为。

真实站点结果是本次设备与网络环境的观测；不将静态解析通过等同于所有上游线路均可播放。

## 最终验证记录

浏览器、完整视频播放器、站点目录、目录提取、正文解析、自定义源、RSS 视频回归均通过；生产构建和 lint 通过，修改文件没有新增 lint 告警。播放器状态用例为 32 项；新增目录用例 7 项、媒体候选/线路用例 4 项。Cloud/Local Java 编译通过，原生单测 282 项、零失败；最终 Cloud Debug APK 构建、覆盖安装及截图对应视频复测通过。

一次完整视频套件复跑中，未修改的 `media-range.test.ts` 本地 HTTP fixture 出现 `fetch failed`。没有改动或放宽该用例；其独立重跑和最终完整 `test:video-player` 重跑均通过。记录这一执行异常，不将它归因于尚未确认的生产代码问题。
