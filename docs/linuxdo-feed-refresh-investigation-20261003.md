# LinuxDO 刷新、频道与新闻预览图排查

基线：`beta`，`9a75fef23b7e361aeb0869fe8bfa41d78e057fe1`。

## 根因与修复

| 问题 | 代码中确认的原因 | 修复 |
| --- | --- | --- |
| 发现页失败后难以恢复 | 大厅没有刷新入口，默认精选页不展示分类/标签错误；失败也被标为目录已加载 | 大厅、分类讨论和标签讨论接入下拉刷新；大厅增加刷新按钮和错误重试；目录只有全部成功才标记已加载 |
| 消息页无法刷新 | 通知错误按钮仅清除提示，刷新依赖重新进入或页面可见性事件 | 通知和私信增加刷新按钮、下拉刷新、错误重试；保持当前消息分类；刷新与分页互斥 |
| 返回列表位置异常 | FeedView 首次渲染空列表，再通过 effect 和下一动画帧恢复内容/位置 | 首次渲染直接使用频道缓存；在布局阶段恢复位置；离开和切频道前保存位置；频道和账号分别挂载，旧请求不能回写 |
| 频道切换与生命周期 | 切频道复用 FeedView 状态，缓存恢复还排队到下一帧；离开列表的请求没有失效清理。热门、新、未读的接口映射本身正确，尚未复现真实账号上的“无效”现象 | 频道和账号分别挂载；同步保存并恢复各频道位置；离开时使请求失效；真实 API 客户端回归覆盖频道请求、迟到响应及验证失败后刷新 |
| 新闻大图尺寸不稳定 | 大图高度依赖可被错误态收起的图片子节点；图片入场动画长期保留 transform | 外层固定大图高度，失败时保留图片框；入场动画结束后释放变换层 |
| 预览遗漏或空白 | RSS 嵌套媒体图片、多个媒体节点及懒加载图片提取不完整；非图片附件可能成为封面 | 提取媒体组、媒体缩略图和懒加载图片，处理相对地址，过滤音视频与文档；命名空间合并后的正文取值跳过空媒体节点 |

原生授权的 `one_time_password` Key 只用于兑换 Cookie 会话，成功后清除；普通请求继续使用现有 `browser-session` 路径，未修改 Android 原生鉴权。

新闻条目没有提供具体 URL，因此预览问题通过受控 RSS/HTML 样本验证。大图失败时的尺寸保持已有组件回归测试；截图所示 Android 偶发合成裁切尚未进行真机复现与复验。

## 验证

- 新增 `community-refresh-view.test.tsx`：发现加载失败后重试、通知和私信刷新、触摸下拉刷新、StrictMode 生命周期、浏览器会话下真实 API 客户端的快速切频道和迟到响应、验证失败重试、从帖子返回缓存列表时在下一帧前恢复位置、大图错误态保留完整尺寸。
- 新增 `feed-preview-images.test.ts`：媒体组、多个媒体节点、懒加载图片、非图片附件及无图正文。
- 恢复基线 FeedView 后，位置恢复回归测试失败；恢复修复后通过。预览提取与发现失败恢复测试也在修复前失败。
- TypeScript 检查、生产构建、LinuxDO 服务与阅读同步测试、相关解析/图片/手势/兼容性测试通过。Lint 无错误，保留仓库已有警告。
- `international-sources.test.ts` 的分类名断言失败：预期“中文公共媒体”，实际“中文公共”。已在干净基线复现。
- `test:cache` 在 Node 环境失败：`storage.ts` 的调度器访问不存在的 `window`。已在干净基线复现。
- 未修改 Android 原生代码。当前环境没有可用的 Android 构建与设备验收工具链；频道在真实账号下的服务器结果、截图中的偶发裁切仍需真机复验，不能据 DOM 测试声称全部现象已消失。

没有新增生产依赖、存储格式或云端请求。RSS 配图解析仍在客户端完成，不为每条新闻额外抓取全文。
