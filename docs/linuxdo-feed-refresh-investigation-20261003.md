# LinuxDO 刷新、频道与新闻预览图排查

基线：`beta`，`9a75fef23b7e361aeb0869fe8bfa41d78e057fe1`。

## 根因与修复

| 问题 | 代码中确认的原因 | 修复 |
| --- | --- | --- |
| 发现页失败后难以恢复 | 大厅没有刷新入口，默认精选页不展示分类/标签错误；失败也被标为目录已加载 | 大厅、分类讨论和标签讨论接入下拉刷新；大厅增加刷新按钮和错误重试；目录只有全部成功才标记已加载 |
| 消息页无法刷新 | 通知错误按钮仅清除提示，刷新依赖重新进入或页面可见性事件 | 通知和私信增加刷新按钮、下拉刷新、错误重试；保持当前消息分类；刷新与分页互斥 |
| 返回列表位置异常 | FeedView 首次渲染空列表，再通过 effect 和下一动画帧恢复内容/位置 | 首次渲染直接使用频道缓存；在布局阶段恢复位置；离开和切频道前保存位置；频道和账号分别挂载，旧请求不能回写 |
| 新、未读等频道异常 | Android 保存了 User API Key，但普通原生请求没有调用 `applyHeaders`；浏览器兼容路径还可能使用另一个 Cookie 身份 | 普通请求携带原生凭据；使用 Key 时不混入 Cookie，不降级到另一个浏览器身份。保留明确指定的第一方阅读同步路径 |
| 新闻大图尺寸不稳定 | 大图高度依赖可被错误态收起的图片子节点；图片入场动画长期保留 transform | 外层固定大图高度，失败时保留图片框；入场动画结束后释放变换层 |
| 预览遗漏或空白 | RSS 嵌套媒体图片、多个媒体节点及懒加载图片提取不完整；非图片附件可能成为封面 | 提取媒体组、媒体缩略图和懒加载图片，处理相对地址，过滤音视频与文档；命名空间合并后的正文取值跳过空媒体节点 |

新闻条目没有提供具体 URL，因此预览问题通过受控 RSS/HTML 样本验证。大图失败时的尺寸保持已有组件回归测试；截图所示 Android 偶发合成裁切尚未进行真机复现与复验。
